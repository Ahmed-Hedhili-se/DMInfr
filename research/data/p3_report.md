# Phase 3 (SQ3): is this a diffusion problem or an MoE problem?

Generated by `python -m research.sq3` (tables below the summary). Spend:
$3.45 of the $4.50 Phase 3 cap. That covers the OLMoE weight fetch ($0.007),
the n=5 smoke test ($0.29), the n=200 self-churn and telemetry run ($0.47),
and the main run ($2.68: 4 arms × 805 questions, B=64, A100-40GB).

## Summary

- **OLMoE's router is far less fragile than LLaDA's, though only moderately
  less flat.** On the same 200 prompts:
  - entropy / log 64: 0.913 vs 0.974;
  - top-1 weight: 8.7% vs 4.5%;
  - median 8th–9th logit gap: **22 bf16 ULP** vs 0.9;
  - bf16-vs-fp32 top-8 flip rate: **1.1% (prefill) / 1.3% (decode)** vs
    23.5% on LLaDA's prompt tokens.
  - Flatness by entropy and fragility by ULP margin are different
    properties. Fragility depends on the logit gaps relative to the bf16
    grid at their magnitude. Logit magnitudes were not recorded, so *why*
    OLMoE's gaps are 25× wider in ULP is unmeasured.
- **Yet OLMoE churns almost as much as LLaDA.** On the same 802 questions
  (uncapped in both controls):
  - fp32 everywhere churns 19.6% [17.0, 22.5] of OLMoE's strict answers
    against 24.7% [21.8, 27.8] for LLaDA;
  - fp32 on the prefill / prime pass only: 20.1% vs 23.6%;
  - ±1 ULP noise: 20.7% vs 25.1%.
  - Accuracy is unchanged in every OLMoE arm (McNemar p ≥ 0.18). Control
    accuracy on these questions is 55.8% for OLMoE and 86.9% for LLaDA.
- **The dose-response curve doesn't transfer across architectures.**
  - OLMoE's ~250 flips per question under fp32 everywhere are ~700× fewer
    than LLaDA's (170,735), and ~20× fewer than LLaDA's smallest arm
    (finalize only, 4,875).
  - LLaDA's flip-only fit predicts 0.1% churn at that dose, and its
    cache-weighted fit 2%. OLMoE sits at ~20%.
  - Per flip, autoregressive greedy decoding is two orders of magnitude more
    sensitive. Under greedy AR decoding, one changed token anywhere sends
    the whole continuation down a different path (median first divergent
    token among diverged questions: 23–26; corrected from 63–82, see the
    retraction).
- **Similar churn, reached by opposite routes** (corrected; see the
  retraction below).
  - Churn = P(output diverges) × P(answer changes | diverged).
  - LLaDA: its outputs always diverge (100%), and a divergence changes the
    answer 23.6–25.1% of the time.
  - OLMoE: its outputs diverge on only **50–55%** of questions; under fp32
    everywhere, about half of the 802 generations come out token-identical.
    But a divergence changes the answer **38–40%** of the time.
  - So the flat router makes divergence certain, while greedy AR makes each
    divergence costlier. Their products land at similar churn.

> **Retraction (2026-10-01).** An earlier version of this report said that
> OLMoE diverged on 88–92% of questions, and that churn given divergence was
> the same in both models (22–23% vs 24–25%). That was a bug in
> `ar_divergence`: it compared the batch's padded output tensors, whose
> trailing padding length depends on when the *batch* finished. Two
> identical generations therefore counted as diverging "at the end" (~900
> spurious divergences at tokens 160–255, all with 0% churn). The function
> now compares content up to EOS. The churn figures themselves did not
> change; only the divergence split did.
- **Fragility belongs to the (model, question) pair, not to the question.**
  - Cross-model rank correlation of per-question churn: ρ = 0.12 [0.05, 0.19].
  - Questions churned under fp32 in both models: 45, against 38.8 expected
    by chance.
  - In both models churn concentrates on questions the control gets wrong:
    OLMoE 35% vs 7%, LLaDA 64% vs 19%. The fragile questions are each
    model's own uncertain ones.

**Answer to SQ3.** The ~20–25% outcome churn under router perturbation is not
specific to masked diffusion and not caused by a flat router. An
autoregressive MoE with a much sharper router (1% flip rate, 22 ULP median
margin) shows nearly the same churn.

The diffusion-specific part is how much routing noise LLaDA-MoE generates:
~25% flip rate, from near-uniform layers 0 and 15 and from re-routing every
masked position at every step. That noise makes divergence certain. OLMoE's
sharp router lets half its generations through untouched, but each OLMoE
divergence is more likely to change the answer.

OLMoE's router is much sharper, so the raw churn difference (≈ 5 points)
can't be read as an AR-vs-diffusion effect. The two models reach similar
churn through different factors.

**Caveats.**
- OLMoE was run on 805 questions (the questions uncapped in LLaDA's
  control), not 1319, to fit the Phase 3 cap. That is an easier subset:
  LLaDA scores 86.9% on it against 75.7% overall.
- OLMoE's prompt uses its own chat template, so the two models don't see
  byte-identical inputs.
- OLMoE flips are measured on its control trajectory over the first 200
  questions.
- The noise arm's flip count is model-based, and that model failed its own
  check on LLaDA, so treat its x position as rough.
- The 22 ULP median for OLMoE is interpolated in a histogram whose top
  finite bin is [32, 64) ULP, so it is coarse.

## SQ3: autoregressive MoE (OLMoE-1B-7B-0924-Instruct) vs LLaDA-MoE

Setup: HF transformers 4.53.2, bf16, SDPA attention, greedy, max_new_tokens=256, batch 64 left-padded, A100-40GB. Same system prompt and 4-shot GSM8K user prompt as LLaDA, rendered by OLMoE's chat template: `<|endoftext|><|system|>\n{system}\n<|user|>\n{prompt}\n<|assistant|>\n` (tokenized without extra special tokens; the template supplies BOS). Perturbation: a forward hook on each layer's `mlp.gate` replacing its output (HF code untouched). Questions: the 805 questions uncapped in LLaDA's control (budget cap for Phase 3, as instructed). OLMoE capped = control hit 256 new tokens without EOS.

### Determinism

Two control runs, same batches (n=200, B=64): 200/200 token-identical. Telemetry hook inert: control_tel is the first of the two.
